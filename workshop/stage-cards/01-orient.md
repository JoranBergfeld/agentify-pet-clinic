## Goal

Learn how the system works now. Do this before you choose what to change.

## What can go wrong

Changing the system based on guesses about the code, tests, setup, rules, or
product needs.

## What to record

- Run and test commands, with their results.
- The code area you may change and the public test that checks it.
- The Azure resources and deployment path you need.
- Repository rules and limits.
- Facts, assumptions, and open product questions kept separate.

## Optional Copilot help

`/codebase-design` can help you find code boundaries and tests. Another method
is fine if it gives the same evidence.
